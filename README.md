ネットワーク、データベース、Linux、PowerShell、基本情報技術者試験の学習用に作った、ブラウザで動く 7 つのツールです。

**公開ページ：** https://yamagata-inaka.github.io/study-tools/

| ツール | 内容 |
|---|---|
| [ルータ基本設定ドリル](https://yamagata-inaka.github.io/study-tools/router-drill/) | Cisco IOS ルータの初期設定を疑似コンソールで練習する |
| [サブネット計算ドリル](https://yamagata-inaka.github.io/study-tools/subnet-drill/) | CCNA のサブネット計算を反復練習する |
| [MySQL 基本操作ドリル](https://yamagata-inaka.github.io/study-tools/mysql-drill/) | MySQL の接続、SQL、トランザクション、権限を疑似コンソールで練習する |
| [Linux サーバー引き継ぎコース](https://yamagata-inaka.github.io/study-tools/linux-course/) | 1 台のサーバーを 12 ステージで引き継ぐ。前の作業の上に次の課題が積み上がり、最後は障害対応 |
| [Linux 基本操作ドリル](https://yamagata-inaka.github.io/study-tools/linux-drill/) | LinuC レベル1・LPIC-1 の範囲の操作を疑似 bash で練習する |

| [科目B 完走コース](https://yamagata-inaka.github.io/study-tools/kamoku-b/) | 基本情報技術者試験 科目B を 171 問・16 ステージで対策する |

## 制作の役割分担

このリポジトリは AI（Anthropic の Claude、Claude Code）を使って作りました。

| 担当 | 内容 |
|---|---|
| **制作者** | 何を作るかのアイデア、実際に使っての問題発見、修正内容の決定、公開するかの判断と責任 |
| **Claude** | コードの実装、問題と解説の作成、原本との照合、テスト、この README の執筆 |

コードは制作者が 1 行ずつ書いたものではありません。以下の「設計」の説明も、実装内容をもとに Claude がまとめたものです。

## 全体の設計

- **サーバーを持たない：** すべて静的な HTML と JavaScript です。ビルドは不要で、ファイルをそのまま配信できます。
- **データを外部に送らない：** 成績や設定は閲覧者のブラウザの `localStorage` にだけ保存します。外部から読み込むのは Google Fonts だけです。
- **依存を増やさない：** フレームワークやライブラリを使っていません。

## ルータ基本設定ドリル

**目的：** 実機がない環境でも、コマンド入力から設定確認までの流れを手で覚えられるようにします。

- **構文木によるコマンド解析：** コマンドを木構造で定義し、実機に近い省略入力と Tab 補完を実現しています。省略形を禁止するモードもあります。
- **設定の状態で採点：** 入力履歴ではなく最終的な設定を採点するので、順序が違っても結果が正しければ正解になります。
- **つまずきの再現：** 打ち間違いで名前解決を待たされる動作などを再現し、`no ip domain-lookup` が必要な理由を体感できます。
- **4 つの学習形式：** 通し練習、一問一答、四択、早見表を切り替えられます。ランダム問題では値が毎回変わります。

初期設定の練習に必要な範囲だけを扱う模擬で、実機の完全な再現ではありません。パスワードのハッシュ表示なども練習用です。

## サブネット計算ドリル

**目的：** サブネット計算を、考え方を理解したうえで素早くできるようにします。

- **32 ビット整数として計算：** IPv4 アドレスを符号なし 32 ビット整数として扱います。JavaScript のビット演算は符号付きになるため、`>>> 0` で符号なしに戻しています。
- **問題の自動生成：** 3 段階の出題範囲（`/24`〜`/30`、`/16`〜`/30`、`/8`〜`/30`）と 11 種類の問題形式を選べます。
- **2 進数の解説：** 答え合わせのあと、ネットワーク部とホスト部を 2 進数で確認できます。
- **入力の補助：** 全角の数字やピリオドも受け付け、IP アドレス欄では `.` を自動で補います。

## MySQL 基本操作ドリル

**目的：** サーバーを用意しなくても、ログインから SQL の実行、権限の確認までの流れを手で覚えられるようにします。

- **SQL を解釈する自作エンジン：** 字句解析、構文解析、名前解決、実行を JavaScript で実装しています。結合、集計、サブクエリ、外部キー、トランザクション、権限を扱えます。
- **結果と状態で採点：** 入力した文字列ではなく、実行後のデータや定義、表示された結果を採点します。別名を付けた SQL など、書き方が違っても結果が正しければ正解です。
- **つまずきの再現：** `;` を忘れたときの `->` プロンプト、引用符の閉じ忘れ、WHERE のない UPDATE、外部キー違反、権限不足を、実物と同じ表示で体験できます。
- **4 つの学習形式：** 通し練習（15 項目）、一問一答（44 項目）、四択（64 問）、早見表を切り替えられます。通し練習のランダム問題と一問一答では値が毎回変わります。

**実物との比較：** MySQL 9.7.2 に同じ SQL を流し、出力を比べました。

| 比較した内容 | 文の数 | 一致 |
|---|---|---|
| エラー文や表示形式を確かめる SQL | 208 | 202 |
| 3 問の模範解答、一問一答の模範解答、四択の根拠になる動作 | 568 | 568 |

比較では実行時間を除きました。2 つ目の比較では、ORDER BY のない結果の行順も問いません。1 つ目で一致しなかった 6 文の内訳は、行順が保証されない結合 1 文、実行時刻を含む結果 2 文、対象外にした UNION とビューの 3 文です。予約語の一覧は、実物の `information_schema.KEYWORDS` から取得しました。

基本操作の範囲だけを扱う模擬で、実機の完全な再現ではありません。ビュー、トリガー、ストアドプロシージャ、ウィンドウ関数などは実行できません。`root` の `SHOW GRANTS` は簡略化しています。

## Linux 基本操作ドリル

**目的：** サーバーを用意しなくても、LinuC レベル1・LPIC-1（101・102）で問われる基本操作を、コマンドを打って覚えられるようにします。

- **疑似 bash と仮想ファイルシステム：** シェルの字句解析、ブレース展開、変数とコマンド置換、グロブ、パイプ、リダイレクトを JavaScript で実装しています。ファイルは所有者、権限、SUID・SGID・スティッキービット、ハードリンクとシンボリックリンクを持ち、権限の判定もカーネルと同じ考え方で行います。
- **状態で採点：** 入力した文字列ではなく、作られたファイルの中身、権限、所有者、ユーザーとグループの設定を採点します。書き方が違っても、結果が正しければ正解です。
- **つまずきの再現：** `sort f > f` でファイルが空になる、`usermod -G` に `-a` を付けないと補助グループが置き換わる、`sudo echo x > /root/f` が失敗する、グループの追加はログインし直すまで反映されない、などを実物と同じ動きで体験できます。
- **4 つの学習形式：** 通し練習（15 項目）、一問一答（45 項目）、四択（132 問、101・102 で絞り込み可）、早見表を切り替えられます。通し練習のランダム問題と一問一答では値が毎回変わります。

**実物との比較：** Rocky Linux 9（RHEL 9 互換）のコンテナに同じ初期状態を作り、206 のコマンド行の標準出力と標準エラー出力を比べました。日時は比較から除いています。

| 比較した内容 | 行の数 | 一致 |
|---|---|---|
| ファイル操作、テキスト処理、権限、ユーザー管理、アーカイブ、サービスのコマンドとエラー文 | 206 | 193 |

一致しなかった 13 行の内訳は次のとおりです。
- ドリル側を直したもの 2 行：`systemctl status` の末尾の空行、空のパスワードのロック解除。直した後のコンテナでの再比較はしていません。
- 比較の環境によるもの 11 行：
  - find の出力順（ディスク上の順で決まり、一定しない）
  - 端末の有無で変わる表示 5 行（tar、rm の確認、alias、exit）
  - polkit を入れていない比較用コンテナでの systemctl の権限エラー 3 行
  - sed の一時ファイル名（乱数）
  - ディレクトリのリンク数（コンテナのファイルシステムの事情）

polkit がある端末では、一般ユーザーの `systemctl start` がドリルと同じ `Interactive authentication required.` になることも確認しました。sudo、su、passwd のパスワード入力の流れ（sudo の初回の注意書き、3 回の失敗、passwd の聞き直しと弱いパスワードの警告）は、疑似端末で実機を動かし、表示を目で照合しました。この比較で、一般ユーザーの umask が 022 であること、RHEL 系には `/usr/bin/cd` があり `sudo cd` がエラーにならないことが分かり、ドリルに反映しています。

基本操作の範囲だけを扱う模擬で、実機の完全な再現ではありません。vi などのエディタ、if・for を含むスクリプト、バックグラウンド実行、パッケージ管理、cron は実行できず、四択で扱います。`ps`、`ip`、`df` などの出力は用意した値です。

疑似 Linux 環境（シェル、ファイルシステム、コマンド）は `linux-drill/engine.js` にまとめ、次の「Linux サーバー引き継ぎコース」と共有しています。

## Linux サーバー引き継ぎコース

**目的：** コマンドを 1 つずつ覚えるだけでなく、1 台のサーバーを運用する流れの中で使いこなせるようにします。基本操作ドリルと同じ疑似 bash を使い、学び方を変えたコースです。

- **作業を持ち越す 12 ステージ：** 前任者のメモに沿って、作業場所づくり → ログの集計 → 権限 → メンバー追加 → Web サーバーの起動 → バックアップ、と進めます。前の課題で作ったディレクトリや設定の上に、次の課題が積み上がります。
- **最後は障害対応：** 「ログインできない」「403 になる」「ディスクがいっぱい」「sudo が使えない」「スクリプトが動かない」の 5 件を、症状だけを手がかりに、ログや権限を調べて直します。
- **完走の条件：** 72 課題（作業 49、確認テスト 23）をすべて最後に正解した状態が完走です。科目B 完走コースと同じく、初回の正誤と最後の正誤を記録します。
- **先に進めなくならない仕組み：** 飛ばした課題や途中からの再開では、それより前の課題の模範解答を自動で適用して状態を作ります。途中で大事なファイルを消しても、課題を選び直せば元に戻ります。
- **サーバーの状況パネル：** サービスの稼働、ディスク使用率、ユーザーを端末の横に表示し、操作のたびに更新します。

模範解答で最初から最後まで進めて全課題がクリアになること、どの課題から始めても模範解答でクリアできることを、ヘッドレス Chrome の自動テストで確認しています。

## PowerShell 修練帳

**目的：** Bash との違いであるオブジェクトのパイプラインを軸に、PowerShell の基本からサーバー管理、リモート実行までを順番に身につけられるようにします。

- **章ごとの流れ：** 全 8 章を「解説 → 実技 → 確認テスト」の順に進めます。実技は 30 問、確認テストは 24 問で、付録に Bash との対応表があります。
- **パターン照合による判定：** 入力を正規化してから正規表現で照合します。エイリアス、大文字小文字、空白の違いは同じものとして扱います。
- **つまずきの指摘：** `==` や `>` での比較、`grep` などの Bash のコマンド、`Format-Table` の後ろにつないだパイプなど、よくある誤りには理由を示します。
- **Windows 専用の課題の表示：** PowerShell 7 は複数の OS で動きますが、Windows でしか使えないコマンドの課題には `WIN` の印を付けています。

PowerShell の実行環境ではありません。実技の出力は用意したサンプルで、入力したコマンドは実行しません。判定や出力を実物の PowerShell と比較する検証はしていません。

## 科目B 完走コース

**目的：** 基本情報技術者試験 科目B を、易しい問題から公開問題まで順番に進めて完走できるようにします。

- **分野と難易度で分けたコース：** IPA の問題 71 問とオリジナル問題 100 問を 16 ステージに並べています。セキュリティ問題 50 問は専用の 4 ステージにまとめ、最後は令和 5〜8 年度のアルゴリズムの公開問題です。
- **解く手順を教える解説：** 「設問と選択肢を先に見る」「選択肢の違いを見る」「小さい例でトレースする」といった読み方の手順に沿って解説します。
- **データと画面の分離：** 問題データ、ステージ構成（`course.js`）、画面の処理（`index.html`）を分けています。
- **復習の仕組み：** 問題ごとに初回と最後の正誤を記録し、間違えた問題を解き直せます。

セキュリティ問題の並び順は、問題文の字数、表の数、選択肢の数から計算した読解量の目安です。正答率の実測にもとづく難易度ではありません。

### IPA の問題と原本の照合

71 問すべてについて、問番号と正解が IPA の公表資料と一致することをスクリプトで確認しました。Web 表示のために図表の組み直しや文章化、文言の調整をしているため、各問の出典に「一部改変」と記載しています。解説は IPA によるものではありません。
