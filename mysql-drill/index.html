    落としやすい点
    
        
      
          
    1. 文の最後の ; を忘れると -> のまま止まって見える。エラーではなく入力の続きを待っているだけ。
      2. 
          
    2. UPDATE と DELETE は WHERE がないと全行が対象になる。確認は出ない。先に同じ条件の SELECT で対象を確かめると安全。
      3. 
          
    3. NULL の検索は IS NULL。= NULL は結果が不明（NULL）になり、1 行も一致しない。
      4. 
          
    4. 文字列は単一引用符で囲む。囲まないと列名として読まれ、Unknown column になる。
      5. 
          
    5. order、group、desc、key などの予約語はそのままテーブル名や列名に使えない。library や sql も 9.7 では予約語で、CREATE DATABASE library; は構文エラーになる。
      6. 
          
    6. 外部キーがあると作る順は親→子、消す順は子→親。親の参照先の列にはキーが必要。
      7. 
          
    7. START TRANSACTION なしの更新は、文ごとに自動でコミットされて ROLLBACK で戻せない（autocommit が既定で 1）。
      8. 
          
    8. CREATE、ALTER、DROP、TRUNCATE は暗黙にコミットする。トランザクションの途中で打つと、それまでの変更も確定する。
      9. 
          
    9. AUTO_INCREMENT の番号は、ROLLBACK や重複エラーの後も戻らず、抜けが生じる。異常ではない。
      10. 
          
    10. アカウントは 'ユーザー'@'接続元' の組。host を省くと '%' になり、'app'@'localhost' とは別のアカウントとして扱われる。
      11. 
          
    11. GRANT はユーザーを自動で作らない（ERROR 1410）。先に CREATE USER を打つ。付与の後に FLUSH PRIVILEGES は不要で、9.7 では非推奨の警告が出る。
      12. 
          
    12. Windows の既定の設定では、テーブル名は小文字で保存され、大文字小文字を区別しない。Linux の既定では区別されるので、小文字で統一しておくと移行で困らない。
      13. 
          
    13. 実際の Windows では、mysql が見つからないと言われることがある。bin フォルダーが PATH に入っていないためで、このドリルでは入っている前提にしている。その場合は & "C:\Program Files\MySQL\MySQL Server 9.7\bin\mysql.exe" -u root -p のように打つ。
      14.
